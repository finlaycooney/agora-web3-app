# Profile semantic search, version 1

This checkpoint ranks approved canonical candidate profiles and the current recruiter's own private draft profiles by meaning. It indexes the complete supported profile projection, never raw Telegram conversations, draft evidence, unresolved suggestions, CV bytes, notes, or other recruiters' private drafts. Search ranking is not an eligibility decision: negation and numeric compensation constraints are not reliable semantic filters. No LLM reranking is included.

## Staff API

All endpoints use existing TELEGRAM_INTAKE_ENABLED, staff MFA, private/no-store responses, Origin checks for mutations, and candidates.read plus candidates.write (the existing scoped Mac worker permission boundary). Existing candidate keyword search remains available separately. Candidate sources are organization-shared; drafts and query text/results are owner-private. Scope is `approved|my_drafts|all`, default `approved`; sourceType is `candidate|draft`.

`POST /api/staff/profile-search` accepts:

- `{action:"search",operationId:UUID,query:string,scope,readyOnly:boolean}` → HTTP202 `{queryId,status:"queued",expiresAt}`. Query is trimmed, nonempty, <=2,000 characters/8,000 UTF-8 bytes. Repeating operationId with the same request is idempotent; changed content is409. One active query per owner: submitting a new search cancels the previous unfinished search. readyOnly filters drafts only; approved candidates stay included. Draft ready means all existing required fields plus validated CV and no pending extraction proposals.
- `{action:"retryIndex",scope,readyOnly}` → HTTP200 `{ok:true,retried,remainingFailed}`. Retries at most100 currently eligible failed sources with transient `EMBEDDING_UNAVAILABLE|WORKER_ERROR|ATTEMPTS_EXHAUSTED` errors. It resets attempts/leases while preserving revision, valid manifest and embedded chunks. Validation/oversized-source errors remain visible for attention. Scope, readiness and private ownership apply identically to search. Repeating this action safely retries the next bounded batch; it never restarts healthy or currently leased work.
- `{action:"cancel",queryId}` → `{ok:true}`. Cancels unfinished work and fences late worker acknowledgements.

`GET /api/staff/profile-search?scope=approved&readyOnly=false` → `{coverage,workerAvailable,indexVersion,projectionVersion,chunkerVersion}`. Coverage is scoped to the caller and requested corpus.

`GET /api/staff/profile-search?queryId=UUID[&after=opaqueCursor]` → `{queryId,query,scope,readyOnly,status,results,nextAfter,coverage,workerAvailable,errorCode,expiresAt}`. Status `queued|running|completed|failed|cancelled|expired`. Query text stays out of URLs. Results are empty until completed; partial scans are never labelled complete. Results are paginated25 at a time with no hidden total-result cap, stable order score descending then sourceType/sourceId. Cursor is opaque and query-bound. Every page rechecks current permissions, source visibility and current indexed revision; restricted/merged/deleted candidates and approved/discarded drafts are never resurrected from a cached result.

Result `{sourceType,sourceId,sourceRevision,displayName,headline,location,hasCv,missingFields,score,matchedText,href}`. Score is a cosine ranking value, not a probability or percentage. MatchedText is a bounded (<=500 characters) verbatim excerpt from the matching indexed profile chunk, not a generated explanation. Href is server-derived `/staff/candidates/<uuid>` or `/staff/telegram-intake?draft=<uuid>`. MissingFields uses existing draft requirements; approved candidates return[]. Results display source/privacy label and source profile links.

Coverage `{eligible,indexed,pending,failed,retryable,corpusChanged}` reports eligible profiles, current fully indexed profiles, queued/running profiles, and failed profiles for this scope/filter. The retryable count is always current, including on completed query details, so the recovery control never depends on stale snapshot counts. The other query coverage counts record the search snapshot; corpusChanged indicates a relevant mutation/index publication since it began. Search includes all eligible profiles fully indexed at scoring time. It reports incomplete coverage clearly when pending/failed profiles exist. Expiry is15 minutes. Expired query text/vectors/results are unusable and purged on subsequent authenticated activity; a scheduled purge is a broader-release operational requirement when the Mac is offline.

ErrorCode is null or `EMBEDDING_UNAVAILABLE|INPUT_TOO_LONG|INVALID_RESULT|WORKER_ERROR|ATTEMPTS_EXHAUSTED|SEARCH_TIMEOUT|SOURCE_TOO_LARGE`. Query token overflow returns failed INPUT_TOO_LONG so the recruiter can shorten the query; it never truncates. workerAvailable is recent activity (<=90 seconds), not a promise of immediate completion.

## Projection and indexing

`indexVersion = intfloat/multilingual-e5-small@614241f622f53c4eeff9890bdc4f31cfecc418b3:e5-prefix:l2:384:v1`

`projectionVersion = candidate-profile-v1`; `chunkerVersion = e5-utf8-448-v1`.

The host creates deterministic labelled profile text from the current full name, headline, location, compensation preference, professional summary, current primary/secondary emails, professional URL, and reviewed Telegram identifiers. Drafts use current normalized fields only. Empty fields are omitted; whitespace is normalized deterministically before hashing, without dropping profile sections. The model prefix is not part of projection text. Projection cap65,536 UTF-8 bytes; an oversized legacy profile fails explicitly instead of silently losing its tail. Current normalized profiles fit this bound. CV content extraction is a separate future source type.

Independent sourceRevision is needed: current candidate-upload metadata updates do not always increment candidate.version. SQL triggers increment source revision, invalidate old vectors/leases and queue indexing when projected candidate/draft fields or canonical identifiers change. Candidate insert/public intake, manual saves, extraction field acceptance, approval, merges, corrections and lifecycle restrictions use these triggers rather than editing every caller. Approved source visibility is a transactionally maintained lifecycle ledger: all canonical row mutations retire/requeue its exact source under the canonical row lock; identifier mutations take a canonical FOR SHARE lock before deriving lifecycle and updating its source. Search entry points recheck the existing same-organization candidate permissions on every call, and source RLS enforces that organization. This avoids repeating the identical permission graph for every candidate during an exact corpus scan without bypassing authorization. Result pages additionally read only their bounded canonical profiles through existing RLS. Candidate lifecycle must be active; all other lifecycles retire source text/vectors immediately. Drafts include pending/snoozed/duplicate only; approval/discard retires the private source and approval's canonical candidate queues separately. Pending suggestions alone do not change indexed text. Metadata/readiness changes invalidate query coverage and are rechecked as live filters; they need not rerun unchanged embeddings.

Minimal portable PG17 storage: source projections/index state with leases; chunks and vectors (real[384]); private query jobs; query result source IDs/revisions/scores; scope revision counters. No vector extension/provider schema. New tables have forced RLS; runtime roles get only narrow functions. Candidate invalidation must also work in public-intake context where actor is null: trigger writes only an organization-scoped invalidation for its exact NEW/OLD candidate, and authorized worker projection reads happen later. Existing legacy1200-character draft vectors are not reused by this namespace.

## Worker API

`POST /api/profile-search/worker/{claim,complete,fail}` uses existing scoped worker bearer token, rejects Origin, and rechecks current candidate permissions on every call. No Telegram connection is needed. Any authorized worker in the organization can index shared candidates; only its owner's draft/query work is offered. Host holds the restricted database connection; Mac holds no database credentials.

Claim body `{}` → `{job:null}` or `{job:Job}`. A claim first offers the owner's urgent query, then one bounded index stage. Lease120 seconds, five attempts; expired leases are reclaimed. Jobs are:

- Common `{id,kind,leaseToken,leaseExpiresAt,indexVersion,projectionVersion,chunkerVersion}`.
- `kind:"query"` adds `{query,querySha256}`.
- `kind:"plan"` adds `{source:{sourceType,sourceId,revision,sha256,text}}`.
- `kind:"embed"` adds `{source:{sourceType,sourceId,revision,sha256},manifestSha256,chunks:[{ordinal,startByte,endByte,sha256,text}]}` (1–8 chunks). Host derives exact chunk texts from its immutable source; Mac never supplies arbitrary embedding source text.

Complete common body `{jobId,leaseToken,kind,indexVersion,projectionVersion,chunkerVersion,...}`:

- query: `{querySha256,result:{embedding:[384 finite normalized numbers]}}`.
- plan: `{sourceRevision,sourceSha256,result:{byteLength,chunks:[{ordinal,startByte,endByte,sha256,tokenCount}]}}`.
- embed: `{sourceRevision,sourceSha256,manifestSha256,result:{embeddings:[{ordinal,embedding:[384 finite normalized numbers]}]}}`.

Plan manifests have1–256 chunks, contiguous ordinals starting0 and contiguous non-overlapping half-open UTF-8 byte ranges covering0..byteLength exactly. Endpoints must be UTF-8 boundaries; each exact byte slice hash must match; no omitted tail. Each chunk <=16,384 UTF-8 bytes, <=16,000 codepoints and <=448 pinned-tokenizer tokens including passage prefix/special tokens. Mac obtains this plan from the existing local service's new tokenizer endpoint and maps snake_case fields to this camelCase protocol. Host independently verifies byte coverage/hashes/bounds; token counts are checked by the pinned local tokenizer, not inferred by host character counts. Profile inference packs <=8 chunks and the actual serialized128KiB local request bound. It yields to urgent queries between batches. The existing E5 query/passage prefixes and normalized384-dimensional vectors remain mandatory.

Complete response `{ok:true,status}`; status is `embedding|ready|completed|failed`, with `manifestSha256` on accepted plan and errorCode for terminal query failure. Plan/embedding writes are atomic; no profile is searchable until every chunk for the current revision is present. Same immutable manifest/vector acknowledgement replays are idempotent; changed revisions/hashes/index versions/leases are409. Partial progress is durable, so retry does not restart a long profile or silently mark it indexed. Query completion stores its vector then performs an exact hosted SQL search of ALL eligible ready chunks, with explicit statement deadline/error; it does not require one network roundtrip per chunk page. Benchmark5k/20k/100k chunks before claiming performance at those sizes. Coverage and corpus revision are captured in one statement before ranking, so mutations during ranking conservatively mark corpusChanged. Result pagination selects at most26 ranked source rows before building25 profile DTOs; it never materializes all profile contact data merely to return a page. Query timeout becomes failed SEARCH_TIMEOUT and returns an acknowledged terminal status, not partial results.

Fail body `{jobId,leaseToken,kind,code,retryAfterSeconds}` where kind is query|plan|embed, code `EMBEDDING_UNAVAILABLE|INVALID_RESULT|INPUT_TOO_LONG|WORKER_ERROR`, delay1–3600. Invalid result/input-too-long is terminal; unavailable/worker-error retries up to5 then fails visibly. Never submit an empty success after an embedding failure. Completed receipt replay still rechecks owner authorization and source revision. Request and response sizes are bounded, errors redact profile/query text, and provider calls have deadlines.

## Parallel scope and acceptance

Backend owns this contract, migration20261002180000, new search contracts/operations/routes and DB tests. Worker owns new semantic worker plus local tokenizer/priority service changes. UI owns profile-search controls/results/status with explicit meaning-ranking copy. Root owns CI/release, real runtime/relevance/scale fixtures. Existing candidate browser and draft inbox need scoped links/mode controls, not rewritten data flows.

Required regressions: long tail/CJK/multi-chunk complete coverage; private-owner isolation; query priority under backlog; late index result after edit/approval/merge/restriction; public-intake trigger path; canonical identifier changes; live readiness filter; stale/cancelled/expired query; repeated acknowledgements; all-profile result pagination beyond1000; offline worker/incomplete coverage; exact SQL scale deadline. No raw Telegram evidence or CV text may appear in an approved projection or result snippet.

Shared and owner-private indexing claims use separate indexed, locked single-row selections, avoiding scans of another recruiter’s private backlog. Authenticated expiry cleanup deletes results only for newly expired queries. Five failed indexing attempts remain visible in coverage. Recruiters can retry transient failures in bounded batches; invalid-result and oversized-source failures require correction or operator attention, and changing the profile queues a fresh revision.

Index write operations acquire the shared and current-owner corpus epoch locks before source rows, matching source triggers. The shared/private order is deterministic; exact query ranking and model inference do not hold those write locks. Concurrent private edits therefore fence late index completions without an epoch/source lock inversion.
